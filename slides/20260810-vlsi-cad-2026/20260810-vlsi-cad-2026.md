## Low-Bit Hadamard Rotation

for Hardware-Efficient LLM Quantization

`NSYSU` `S4-1`

<!--

## 背景：量化的敵人

LLM 的 activation 有 **heavy-tailed outlier**

```text
[0.3, -0.5, 0.2, ..., 62.0, ..., 0.4]
                       ↑
              一個離群值綁架整組 scale
```

範圍 ±0.6 → ±62，格子粗 100 倍，其餘全被壓扁

<!--
LLM 量化最大的敵人是 activation 的 outlier。大部分數字很小，但有極少數特別大。

問題不是那個大數字本身，是它綁架了整組的 scale。量化是 x 除以 scale 再四捨五入，本來範圍正負 0.6 可以切很細，混進一個 62 之後範圍變正負 62，格子粗一百倍，其他四千多個數字全被壓扁成同一格。

而且這些 outlier 不能直接砍掉，研究發現它們是模型刻意維持的機制，跟 attention sink 有關。
-->

---

## 現有解法：旋轉

$$y = Wx = (WH^\top)(Hx)$$

$$[10, 0, 0, 0] \xrightarrow{\;H\;} [5, 5, 5, 5]$$

---

正交 → 長度守恆，能量被攤平
$H^\top H = I$ → **數學上完全等價，不是近似**


Hadamard 元素只有 ±1，用 FWHT 是 $O(d\log d)$ 純加減，不需要乘法器

<!--
主流解法是旋轉。正交矩陣乘上去等於旋轉，而旋轉不改變向量長度，只改變方向。能量沒有消失，只是從少數幾個維度攤到所有維度上。

四維的例子：一個 10 集中在第一維，轉完變成四個 5。長度一樣是 10，但峰值掉一半。一般化來說 d 維空間會掉根號 d 倍，4096 維就是 64 倍。

關鍵是 H 轉置乘 H 等於 I，所以這個插入是數學上完全等價的，不是近似。

那為什麼一定要 Hadamard？理論上任何正交矩陣都行，但 4096 乘 4096 的隨機正交矩陣要一千六百萬次乘法，跟原本的 matmul 一樣貴，等於白做。Hadamard 元素只有正負 1，不用乘法器；而且有遞迴結構可以用 FWHT，複雜度降到 d log d。

代表作是 QuaRot 和 SpinQuant。
-->

---

## 但旋轉不是免費的

$$y = \underbrace{(WH^\top)}_{\text{weight → 離線 fuse}}\underbrace{(Hx)}_{\text{ activation → 只能 runtime}}$$

---

| Llama-2-7B, $d=4096$ | |
|---|---|
| 一次 FWHT | **49,152** 次加減 |
| × 7 個 projection × 32 層 | |
| **每個 token** | **約 1,100 萬次額外運算** |

而且現有方法都在 **FP16** 上做 → datapath 寬、吃頻寬

<!--
這裡是這篇的切入點。

公式拆開，左半邊 W 乘 H 轉置——兩個都固定，可以離線先乘好存成新權重，推論時完全免費。這叫 fuse，本質上就是編譯器的 constant folding。

但右半邊躲不掉，因為 x 是使用者輸入才誕生的 activation。

論文把成本算出來了：4096 維一次 FWHT 是 49152 次加減，套用在 q k v o 加上 FFN 的 gate up down 共七個 projection、乘 32 層，每產生一個 token 要多做 1100 萬次運算。

更重要的是，現有方法都在 FP16 上做。這代表加法器要開 16 bit 寬、每次讀寫都是 16 bit、暫存也跟著變大。
-->

---

## 這篇的提問與做法

> ### 旋轉的任務是「重塑分布」
> ### 不是「保存精確數值」

```text
QuaRot： FP16 →       [旋轉 FP16] → 量化 A4
S4-1  ： FP16 → 量化 8-bit → [旋轉 8-bit] → 量化 A4
```

$$y = (WH^\top)\big(H\,Q(x)\big)$$

差別只在 $Q(\cdot)$ 挪到 $H$ 前面

<!--
然後是這篇的核心提問，

它說：旋轉的主要任務是重塑分布，不是保存精確的數值。那全精度真的必要嗎？

這是個好問題，因為以前沒人問過，大家都預設要 FP16。

做法很單純，就是把量化往前挪。QuaRot 是 FP16 進來、FP16 旋轉、再量化到 4 bit。這篇是先量化成 8 bit、用 8 bit 的 datapath 旋轉、最後才到 4 bit。

寫成公式就是 Q 這個量化函數從 H 外面搬到裡面。

直覺上為什麼可以？因為旋轉完反正還要量化成 4 bit，那些精細的小數位遲早會丟掉。與其辛苦保留再丟，不如一開始就別帶著。

另外它還有個細節，旋轉單位用的是 head dimension 的 128，不是 4096。這個節省其實更大，差 55 倍。
-->

## 結果

Llama-2-7B · WikiText-2 perplexity

| W-A | 無旋轉 | FP16 旋轉 | 8-bit 旋轉 |
|---|---|---|---|
| 16-16 | — | 5.47 | — |
| **8-4** | 7.49 | **5.47** | **5.52** |
| **4-4** | **NaN** | 7.71 | 7.96 |

- W8A4 旋轉後**完全追平 FP16 baseline**
- **W4A4 不旋轉直接壞掉** → 旋轉是必需品
- 降到 8-bit 只掉 **0.05**，zero-shot 準確率掉 1.0

<!--
Perplexity 是量模型對下一個字有多困惑，越低越好。

W8A4 是權重 8 bit、activation 4 bit。不旋轉是 7.49，旋轉之後 5.47——跟完全沒量化的 baseline 一模一樣，等於損失完全補回來了。降到 8 bit 旋轉是 5.52，只掉 0.05。

下面 W4A4 更激進。不旋轉直接 NaN，模型整個壞掉。這一格很有說服力，它證明旋轉不是錦上添花，是必需品。

另外還有一組 zero-shot 的實驗，測八個常識推理 benchmark，趨勢一致，W8A4 掉 1 個百分點。

論文的賣點就是：掉 1 個百分點，換 datapath 和頻寬減半。
-->

## 我的觀察

**1. 「省 50%」是推導的，不是量的**

16 bit → 8 bit 字面上就是一半


**2. 旋轉只佔總運算的 0.08%**

旋轉 1,100 萬次加減 vs. matmul 約 140 億次 MAC
省它一半，端到端影響有限

<!--
兩點觀察。

第一，那個省 50% 是從位元數推導出來的，不是量出來的。16 bit 變 8 bit 當然是一半，這是定義。但實際省多少面積、功耗、端到端快多少，論文完全沒有硬體實作。這個不算它藏東西，因為結論裡它自己就說 future work 要整合進 accelerator。

第二，我算了一下比例。1100 萬次聽起來很多，但 7B 模型每個 token 的矩陣乘法大概 140 億次 MAC，旋轉只佔 0.08%。省它的一半對端到端幾乎沒影響。

那價值在哪？我覺得是在 ASIC 的 datapath 面積——FWHT 單元從 16 bit 縮到 8 bit，面積是實在的節省。但這正是論文沒證明的部分。

所以我對它的定位是：演算法可行性驗證，不是硬體論文。但那個提問本身很好，值得後續有人真的做出來。
-->

## Adaptive ViT Accelerator Memory-Aware Tiled-Streaming Architecture

`Chang Gung University` `SUTD` `S9-5`

<!--

## 背景：SOSA 在做什麼
 
**Scale-Out Systolic Array**（EPFL, TACO 2023）
 
單一大陣列（如 256×256）的兩個毛病：
 
- 矩陣**不夠大** → 填不滿，**PE 大量閒置**
- 邊長越長 → **填充與排空的延遲越久**
```text
TPU：  一個 256 × 256
SOSA：  256 個 32 × 32 的 pod，用互連串起來
```

---

## 動機

拿前人架構 SOSA 量出來的開銷拆解

| | SRAM 佔比 |
|---|---|
| 功耗 | **45.8%** |
| **面積** | **75.4%** |


SOSA 把大陣列拆成 256 個 32×32 的 pod，但每個 pod 都要配 buffer → on-chip memory 64 MB

<!--
這是整篇最關鍵的一張圖。

先說 SOSA 是什麼——它是 EPFL 2023 年的工作，Scale-Out Systolic Array。想解決的問題是：像 TPU 那種單一大陣列，小矩陣填不滿、填充排空的延遲又長。所以它把大陣列拆成很多小的 pod，容易填滿、延遲短。

後來還有 SISA 是反方向把小的整合回來，COSA 是讓多個陣列協同。三個都在調同一個旋鈕——陣列要切多碎。

但拆散有代價：每個小陣列都要有自己的 buffer。SOSA 的 on-chip memory 高達 64 MB。

這篇去量了一下，發現功耗 45.8% 是 SRAM，面積更誇張，75.4% 是 SRAM。PE 反而是小頭。

所以它的方向不是去加 PE、也不是調陣列怎麼切，是去砍 SRAM。這跟大家在講的 memory wall 是同一件事。
-->

---

## 問題一：weight buffer 值不值得

SRAM 存在的唯一理由 —— **同一份資料要被讀很多次**

| | 重用次數 | 值得存嗎 |
|---|---|---|
| Activation | tile 內反覆使用 | ✅ |
| **Weight**（batch=1） | **每層只用一次** | ❌ |

```text
傳統：  DRAM → SRAM → PE     
本篇：  DRAM ───→ PE
```

**On-chip memory：64 MB → 37.5 KB**（正規化面積 1.00 → 0.15）

<!--
那怎麼砍？它問了一個很根本的問題：這些 SRAM 到底在存什麼、值不值得存。

SRAM 存在的唯一理由是資料重用。那 ViT 推論的時候什麼東西會被重複讀？Activation 會，因為一個 tile 內的 activation 要跟很多 weight 相乘。但 weight 在 batch 等於 1 的推論裡基本上就用一次，用完換下一個。

只讀一次的東西，你把它從 DRAM 搬到 SRAM 再讀出來，等於白搬一趟。付了面積卻沒省下任何一次 DRAM 存取。

所以它讓 weight 直接從外部串流到 PE，不進晶片。

這裡有個容易誤解的點——會不會變慢？其實不會，因為 weight 本來就住在 DRAM。傳統是 DRAM 到 SRAM 再到 PE，這篇是直達。DRAM 那趟兩種都要付，差別只在要不要多蓋一個中途站。延遲用 double buffering 藏掉，真正的約束是外部頻寬夠不夠餵飽 PE。這點等一下會回來講。

結果是 on-chip memory 從 64 MB 降到 37.5 KB，正規化面積 1.0 降到 0.15。
-->

---

## 問題二：token halting 的不規則

**A-ViT 等方法**把不重要的 token 提前停掉

```text
Layer 1 : ████████████████
Layer 8 : ███░░░░░██░░░░░░
Layer 12: ██░░░░░░░░░░░░░░
```

Token 在矩陣裡是**列** → 停掉 = **整列無效**
但陣列不知道，死列照樣被推進去跑一遍

<!--
第二個問題是 token halting。

ViT 把圖片切成 patch，每個 patch 是一個 token。一張圖裡很多是背景，天空、白牆這種，過了幾層就沒新資訊了。所以 A-ViT 那類方法會動態把它們停掉。

FLOPs 確實降了。但停掉的位置每張圖都不一樣，取決於內容。

這對 systolic array 是災難。Token 在矩陣裡對應一整列，停掉一個就是一整列無效。但陣列不知道哪列是死的，照樣推進去跑一遍，白白消耗 switching power 和搬運頻寬。

這其實就是我們熟悉的「非結構化稀疏對硬體不友善」，只是這裡稀疏的是 token，不是權重。演算法端的自由度，變成硬體端的負擔。
-->

---

## 做法：壓縮 + bypass

```text
壓縮前            壓縮後
活  ████          活  ████
死  ░░░░    →     活  ████
活  ████          活  ████
死  ░░░░          （下面不送）
活  ████
```

- 陣列看到的又是**規則的稠密矩陣**
- 傳播功耗 **100% → 40%**
- 用 zero-prefix accumulation 算位址
  **不需要平行比較器或索引表**

<!--
做法是在進陣列之前先壓縮：把活著的列擠到上面，死列跳過不送。

壓完之後陣列看到的又是規則的稠密矩陣，資料流恢復正常。傳播功耗從 100% 降到 40%。

還有個細節我覺得不錯——壓縮的實作很省。用 zero-prefix accumulation 漸進地累計前面有幾個死列就能算出新位址，不需要大規模的平行比較器或索引表。

這點很重要，因為稀疏加速器最常見的失敗就是索引開銷把節省吃掉了。
-->

## 結果

28 nm ASIC，**有做到 APR**（1.04 × 1.04 mm）· ImageNet-100 attn FLOPs ↓19.22%

| | A³ | SpAtten | TCAS-I | SISA | 本篇 |
|---|---|---|---|---|---|
| Memory (KB) | 80 | 392 | 232 | 10240 | **37.5** |
| PE | 512 | 1024 | 512 | 16384 | **300** |
| Area (mm²) | 2.08 | 1.55 | 1.19 | 221 | **1.08** |
| Freq (MHz) | 1000 | 1000 | 1000 | 1000 | **400** |
| **TOPS/W** | 1.99 | 0.38 | 2.31 | 1.16 | **4.76** |
| **GOPS/mm²** | 105 | 238 | 858 | 148 | **461** |

<!--
軟體端：baseline 是 Swin-T 在 ImageNet-100 上，attention 層 FLOPs 降 19.22%，準確率掉 1.6。

硬體端有做到 28 奈米的 APR，論文裡有實體佈局圖，晶片 1.04 乘 1.04 毫米。

記憶體 37.5 KB 是全場最少，比第二名少一個數量級。面積 1.08 平方毫米也是最小。能效 4.76 TOPS/W 是第二名的兩倍，面積效率 461 僅次於 TCAS-I。

**效率贏，是因為它很小**

吞吐量 0.799 TOPS vs. SOSA 的 317 TOPS，**差 400 倍**

PE 只有 300、頻率只有 400 MHz → 頻寬需求小 → **串流才可行**
若把 PE 加到 16384，串流餵不動，**weight buffer 就非要不可**

<!--
兩點主要觀察。

第一，它的效率贏很大程度是因為它非常小。吞吐量 0.799 TOPS，SOSA 是 317 TOPS，差 400 倍。PE 數也是 1200 對 26 萬。

我不覺得這是造假，小設計本來就該比效率指標，而且論文很誠實地把絕對數字列出來了。但要注意「效率高」和「撐得住即時推論」是兩件事，0.8 TOPS 能不能撐 Swin-T 即時處理，論文沒回答。

第二點跟第一點有關，我覺得是最值得討論的地方。它的 weight streaming 之所以可行，是因為 PE 只有 300 個、頻率只有 400 MHz，需求量小，外部頻寬餵得動。如果把 PE 加到 SISA 那種 16384 個，串流就餵不動，會直接被頻寬卡死，那時候 weight buffer 就非要不可。

所以這個設計是自洽的，但綁在一個特定操作點上。它證明的是「在這個規模下 weight buffer 是浪費」，不是「永遠是浪費」。

第三點小的：τ_h 從 0.5 調到 0.8 砍更多反而更準，可能是正則化效果，但兩組都只跑 250 epoch 而 baseline 跑 300，這個對照本身就不太公平。
-->

# Q & A

<!--
可能被問到的：

Q: 為什麼 W 乘 H 可以離線算好？
A: W 是訓練完就固定的權重，H 是固定的常數矩陣，相乘結果也固定。等於編譯器的 constant folding。

Q: 旋轉為什麼能攤平 outlier？
A: 正交矩陣保持向量長度不變，但重新分配各維度的能量。集中在一維的能量被攤到 d 維，峰值降低根號 d 倍。

Q: 為什麼 activation 比 weight 難量化？
A: weight 是靜態的，可以離線慢慢調 scale，甚至每個 channel 一個。activation 是 runtime 才誕生的，範圍事先不知道；而且矩陣乘法沿 channel 方向加總，per-channel scale 數學上提不出來。

Q: 第二篇的 weight streaming 對 LLM 適用嗎？
A: 不一定。LLM 的 weight 大很多，decode 階段又是 memory-bound，串流的頻寬壓力更大。但如果 batch 開大，weight 重用率上升，那 buffer 反而值得。

Q: 兩篇有沒有可能結合？
A: 概念上可以——S4-1 是量化的前處理，S9-5 是 dataflow，動的是不同層。但 S4-1 針對 LLM 的 decode，S9-5 是 ViT，沒有 decode 階段，場景不同。
-->
